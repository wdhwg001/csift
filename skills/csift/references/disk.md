# Disk: files a session changed (files), rebuilding a file (recover), the plan file (plan)

Read this before reporting which files a session edited or when, before rebuilding a file's content from a transcript (a deleted file, a file as it was at a turn, a deleted plan), and before locating or auditing a plan file or reading whether a plan was approved. For one flag, mode or JSON key, search this file for its name and read that row.

## Contents

- files
- recover

- plan

## files

`csift files TARGET --by file` lists the files a session changed. `--by` picks the detail: `summary` (default: a rollup by the first few directories, measured: `csift files @<uuid> --no-subagents`), `dir`, `file`, `timeline` (one row per mutation). Structured tool calls (Edit, Write, NotebookEdit, and MultiEdit in older transcripts) are authoritative, create against edit read off the paired result, and a failed structured call is left out; Bash mutations are parsed lexically from the command text and always marked `(heuristic)`, and one from a chain whose result errored is kept with `command_errored` true, since which parts ran is unknowable. PowerShell commands are not parsed at all, so a shell write made through Windows' `PowerShell` tool never appears (UNTESTED). Sessions that CHANGED a file is `csift files --glob '**/NAME' --by file`, sessions that merely MENTION it is `csift search 'NAME' -l`. A row is one TRANSCRIPT's changes to one file, not a session's: on a spanning target each subagent that edited the file adds its own row, whose `session_id` is its agent id. So `csift files @<uuid> --no-subagents --by file` lists only the edits the session's own lane made, which on a session that delegates its edits is a small part of them, and `csift files @<uuid> --by file` lists every lane's. For one row per session and file, group by `parent_session_id`:

```sh
csift files TARGET --by file --format json | jq -s -c 'map(select(.kind=="file")) | group_by([.parent_session_id, .path]) | map({session: .[0].parent_session_id, path: .[0].path, total: (map(.total) | add), transcripts: length})'
```

Measured on one session with its subagents: 11,277 rows over 10,022 paths from 777 transcripts; one path carried 177 rows, 176 of them subagent transcripts, which the grouping folds into one row with `total` 1,200 (365 rows with `--no-subagents`). `--by file` rows print in session-id order, not by time (measured: `csift files --glob '**/NAME' --by file` over one projects root), so the latest edit of a file is `csift files --glob '**/NAME' --by file --format json | jq -s 'map(select(.kind=="file")) | sort_by(.last_utc) | last | {parent_session_id, session_id, path, last_local}'`.

`--regex RE` (matched anywhere in the full absolute path, case-exact) and `--glob PAT` (full path; both `*` and `**` cross `/`, measured: `--glob '/Users/*/NAME'` matched files several directories deep) filter before the rollup and AND together.

A Bash path is resolved against the record's own `cwd` (the shell directory Claude Code stamps on every record), so relative and absolute spellings of one file share a row; JSON `resolution` says how: `absolute`, `cwd-joined`, `cd-tracked` (through literal `cd`s in the same command), `unresolved` (kept as typed: `~`, a `$VAR`, an unknowable cwd), with `path_verbatim` when the typed spelling differs; `resolution` is null on a structured tool's row and on a class-marker row (measured: `csift files @<uuid> --no-subagents --by timeline --format json` gave it null on 409 of 464 rows on one session, 337 of them Edit and Write, 72 class markers). Both are JSON-only; the text timeline omits them (measured: `csift files TARGET --by timeline | grep -c cwd-joined` printed 0). A command that changes files it never names prints a class marker instead of a path: `git:<sub>`, `fmt:<tool>`, `interp:<lang>`, `pkg:<manager>`, `extract:<tool>`.

An `external write` row (`external write  <path>  (inferred: file-history vN->vM with no tool record in L<a>..L<b>)`) is inferred from Claude Code's file-history versions: the file's tracked version moved with no tool call in the interval, because the harness rewrote it (`/model`, `/config`, a plugin toggle) or an outside editor did. `files` reports it only for `.claude/settings*.json`; `recover` reports the same inference for the one file it rebuilds, whatever the path. The version bumps themselves are `harness.bookkeeping.file-history` lines (gated: `-t`): `csift search '\.claude/settings[.a-z]*json@v' TARGET -t harness.bookkeeping.file-history` lists the settings-file bumps (measured: the same command with `-c` printed 8 on one session). A mutation on a branch the conversation was rewound past keeps its row, because the write happened: `[abandoned]` and a turn slot `abandoned (root L<n>)`; one above a compaction floor reads `[pre-cut]` with its ordinary turn number (references/survival.md). A text timeline row reads `L248  <local instant>  turn 0  bash (heuristic)  pkg:pnpm  [pre-cut]` (measured: `csift files TARGET --by timeline`). The footer counts Edit-before-Read boundaries (a Read forced by an outside change: a formatter, git, an editor), and a boundaries section follows only when there is at least one.

JSON:

| rows | keys |
|---|---|
| `mutation` (`--by timeline`) | trio, `line`, `path`, `op` (`write`, `edit`, `multi_edit`, `notebook_edit`, `bash`, `external_write`), `ts_utc`/`ts_local`, `turn_index` (null only on an abandoned row), `survival`, `abandoned_root_line`, `is_create`, `heuristic` (true only for Bash), `resolution`, `path_verbatim`, `command_errored`, `detail` |
| `file` (`--by file`) | trio, `path`, per-op counts `write`, `edit`, `bash`, `multi_edit`, `notebook_edit`, `external_write`, `total`, `abandoned` (the share of `total` from abandoned records, never subtracted), `distinct_files`, `first_*`, `last_*`; there is NO `heuristic` key on this row |
| `dir`, `bucket` (`--by dir`, `summary`) | the same counts, the group named in `path` |
| summary | `sessions`, `distinct_files`, `total_mutations`, `edit_before_read_boundaries`, `skipped_lines`, `detail_level`, and the crossing keys |

To keep only files changed by structured tools, filter the per-op counts: `csift files TARGET --by file --format json | jq -r 'select(.kind=="file" and ((.edit+.write+.multi_edit+.notebook_edit)>0)) | .path'`; a filter on `heuristic` goes wrong both ways, because the key is absent there: `.heuristic==false` selects no row and `.heuristic!=true` or `(.heuristic|not)` selects every row (measured on one session: 0, 92 and 92 of 92 rows, against 49 with the count filter). Per mutation: `csift files TARGET --by timeline --format json | jq -r 'select(.kind=="mutation" and .heuristic==false and .op!="external_write") | .path' | sort -u`.

## recover

`csift recover TARGET --file PATH` replays a file's Reads, Writes and Edits from the transcript into a buffer where unseen lines stay explicit gaps and nothing is invented. Pass `--file` the absolute path. It is matched against every file path the scope's records carry, a relative one (a tool call given `a/lib.rs`) taken as the file its record's own `cwd` resolves it to, so the absolute path finds that file's relative writes too. A relative record path on a line with no `cwd` (a file-history snapshot key) is resolved under the transcript's first `cwd`, so in a session that changed directory before its first write that candidate can be a path no record wrote (docs: `csift recover --help`, `--file`; measured on a synthetic session that started in `/fixture/rc/a`, wrote `lib.rs` from `/fixture/rc/b` and snapshot-keyed `lib.rs`: `--file lib.rs --coverage` was refused naming `/fixture/rc/a/lib.rs` and `/fixture/rc/b/lib.rs`, and the first, passed back, replayed 1 history-snapshot event and 0 lines). Every path, the target's and each record's, is compared LEXICALLY: `.` segments drop and a run of `/` collapses to one (a leading `//` stays), so `./a/x`, `a/x` and `a//x` are one file and any of its spellings replays its whole history; a `..` is not resolved (except inside a relative path joined to its record's `cwd`) and a symlink is not followed, so `/tmp/x` and the `/private/tmp/x` it resolves to are two files, each replaying only the events recorded under its own spelling, which can read `complete` on content a write through the other spelling replaced (docs: `csift recover --help`; measured on a synthetic session writing `/fixture/rec2/sp/x.rs` and `/fixture/rec2/sp//x.rs`: `--file x.rs`, `sp/x.rs`, `./sp/x.rs` and each full spelling replayed both writes, 1/1 lines). `--file @plan` rebuilds the session's bound plan file, even a deleted one.

A shorter path is a suffix of whole path components (`app.py` can name `src/app.py`, never `myapp.py`): naming exactly one file in scope it works like the full path, and naming several it is refused by every mode before anything is replayed, exit 1, with the count and the candidates, one per line, the first ten listed and the rest counted as `... +N more (a longer suffix narrows the list)`: ``csift: error: --file `<suffix>` names <N> distinct files in scope - replayed as one file it would stitch their edits into one buffer, ...``; pass one of the listed paths: each candidate, passed back as `--file`, replays that file alone, and one that the other candidates end with (a relative path from a transcript with no `cwd`) adds a note on stderr (docs: `csift recover --help`; measured on a synthetic session whose Writes named `a/lib.rs` and `/fixture/rec/b/lib.rs` under `cwd` `/fixture/rec`, and on one whose Writes named both relatively: `csift --claude-home FIXTURE recover @<uuid> --file lib.rs --coverage` exited 1 listing `/fixture/rec/a/lib.rs` and `/fixture/rec/b/lib.rs`, while `--file /fixture/rec/a/lib.rs`, `--file /fixture/rec/b/lib.rs` and `--file a/lib.rs` each exited 0 with 1/1 lines; a synthetic session writing twelve files named `lib.rs` listed ten and `... +2 more`; on a live session a basename refusal listed four absolute paths, a file-history line's bare name resolving into one of them, and each of the four replayed alone, exit 0; a partial component printed `no recoverable history for <name> in range`, exit 0 under `--coverage`).

Exactly one mode per run (docs: `csift recover --help`; two mode flags exit 2):

| mode | prints | fails when |
|---|---|---|
| default (restore) | the final content as raw bytes, nothing else on stdout, a note on stderr | the session never saw the whole file: it names the ranges it has and lacks and points at `--salvage`, exit non-zero |
| `--salvage` | the final state as a numbered listing, each known line as `    4  <text>` and each unknown run as `??? lines A..B unknown` | never |
| `--at WHEN` | the state as of WHEN, in the same listing; WHEN also takes `@turn:N`, `@line:N` (a transcript line, the event on line N included) and `@latest` | never |
| `--patches` | unified diffs, split at integrity boundaries, each with its line, turn and instant | never |
| `--coverage` (alias `--dry-run`) | covered ranges, boundaries, per-op counts; no content | never |
| `--list-backups` | Claude Code's own checkpoint store for the path (instant, bytes, `@vN`, store path); needs a literal absolute `--file`, reads no transcript, so no target is needed | never |

An Edit or Write lands at its result's line, not its call's: `--at @line:N` on the call's line shows the state before it (measured on a synthetic session whose Write called at L2 and returned at L3, and whose Edit called at L5 and returned at L6: `--at @line:2` printed `no recoverable history ... as of @line:2`, `@line:3` the written line, `@line:5` still the old line, `@line:6` the edited one). The text output of `--salvage`, `--at` and `--patches` shortens each line over about 400 characters to an excerpt ending `… (+N chars)`; the default restore, `--out` and JSON `lines` keep every line whole (docs: `csift recover --help`, `--out`; measured: a 603-character line printed 425 characters under `--at @latest` and `--salvage`, and 603 in the restore and in JSON).

The listing is a reading aid, never the file: `--out` under `--at` or `--salvage` writes that listing, line numbers and gap lines included, so an `--out` naming a source path replaces the source with a listing (measured on a synthetic session: `--at @turn:0 --out FILE` wrote `    1  app line 1` and four more numbered lines; `--salvage --out FILE` on a file read in part wrote `??? lines 1..3 unknown`, three numbered lines and `??? lines 7..10 unknown`). The file's bytes as of a turn come from JSON, whole only when the snapshot's `gaps` is empty: `csift recover TARGET --file PATH --at @turn:N --format json | jq -r 'select(.kind=="snapshot") | .lines[].text'` (measured: the five lines it printed for `@turn:0` matched the content the session wrote, byte for byte; on the file read in part `gaps` read `[[1,3],[7,10]]`).

`--file-lines N|A..B|N..|-k` narrows to lines of the rebuilt FILE (the one flag that addresses lines of the file; every other `line` in csift is a transcript line). `--turn`, `--since` and `--until` window the replay; a write from an abandoned record is still replayed, because it reached the disk, and is stamped `turn abandoned (root L<n>)`.

What the replay can use beyond the tool calls: a small set of shell commands whose output IS the file. A write anchor is a heredoc through `cat` or `tee` with a quoted delimiter (an unquoted one only with a body free of expansions), a literal `echo`/`printf`, or `truncate -s 0`; each such write inside a pipe or a `;`/`&&`/`||` chain anchors, provided the whole command's result is clean (no error, empty stderr, not interrupted) and no other segment writes the same path. A read anchor is a single simple command, `cat F`, `head -n N F` or `sed -n 'A,Bp' F`, with a clean result. A `Read` that the tool cut at its token budget anchors only the whole lines it returned, never the whole file (UNTESTED). Anything else that touches the file (a variable target, an interpreter heredoc, an ssh heredoc, `sed -i`, `tail`) becomes a boundary: the replay marks where trust ends and adds no content (docs: `csift recover --help`).

Claude Code's own signals become boundaries or notes: a Bash result's `staleReadFileStateHint` naming the file is a hard `hint_modified` boundary; an Edit flagged `staleRecovered` is a `stale_recovered` note (the disk had drifted, the edit applied); a version jump in Claude Code's file-history is an `external_write` boundary, `external write (inferred, snapshot vN->vM, no tool record since L<line>)`, and where the checkpoint blob survives with a matching instant the replay compares against it and continues from the checkpoint's bytes. `/rewind`'s "Restore code" writes nothing to the transcript; the next prompt's `edited_text_file` attachment is its trace (docs: `csift recover --help`).

Every mode counts what the replay could not include: Bash mutations of the file, commands that change unnamed files (`git:`, `fmt:`, `pkg:`, `extract:`, `interp:`; measured: `csift recover @<uuid> --no-subagents --file PATH --coverage` listed `git:checkout`, `git:merge`, `git:reset` and `pkg:pnpm` on one file), PowerShell commands; when any exist it prints a ready-to-run, time-bounded `csift search` for the window. `complete` means complete from the tool stream only; a change made outside any recorded tool, with no later Read, leaves no trace at all (docs: `csift recover --help`).

The checkpoint store `--list-backups` reads is written by the structured file tools and by an approved in-place `sed` preview, never by other shell writes or manual edits; it is pruned over time, and its `@vN` counters restart per session directory, so a listing is not a history and csift never merges it into a reconstruction (docs: `csift recover --help`).

Writing the result:

| action | irreversible: the command, its preview, the rule |
|---|---|
| restore onto disk or save a snapshot | irreversible: `csift recover TARGET --file PATH --out OUT` replaces OUT with the restored bytes, or under `--at`, `--salvage` or `--patches` with that mode's text, a numbered listing for the first two (above); in restore mode stdout stays empty, in the others the summary still prints, and `--coverage` ignores `--out`; OUT is left untouched when nothing was reconstructed in range (exit 0, stderr `note: nothing reconstructed in range; --out file <OUT> left untouched`) and when a restore fails (exit 1) (measured on a synthetic session: `--at @line:1 --out` and a default restore of a file read in part); preview with `ls -l OUT` and the same command without `--out`, which prints to stdout what OUT would receive (outside restore mode with lines over about 400 characters shortened, above) and writes nothing; run only after the user's reply to that preview says go |
| batch-recover many files | irreversible: `csift recover TARGET --files-from LIST --out-dir DIR` writes each listed file to `DIR/<absolute path without its leading slash>` plus `recovery-report.tsv` (one scan for all of them; the report's columns include `boundaries`, `bash_file` and `bash_opaque`; existing files are skipped and reported unless `--force`, which overwrites them; a `partial` file is written as its known lines with the gaps removed and no marker, so only the report's `status` column says it is incomplete; every run replaces `recovery-report.tsv` with that run's rows (measured on a synthetic session: a file known on 3 of its 10 lines was written as those 3 lines, report status `partial`; a second run listing one file left a one-row report); a listed line that names several files, by the `--file` rule above, is not replayed: its report row reads `ambiguous`, stderr names the manifest line and its candidates, and the summary counts it beside the recovered files, never among them, docs: `csift recover --help`); preview with `csift recover TARGET --file PATH --coverage` for each PATH in LIST over the same target and window, and `ls -lR DIR`, which also shows the `recovery-report.tsv` the run will replace; run only after the user's reply to that preview says go |

## Before trusting a reconstruction

Run `csift recover TARGET --file PATH --coverage` first; read the hard and soft boundary counts and the list of commands in the window; run the `csift search` it prints if any; only then trust a restore or a salvage. A restore that succeeds says so on stderr in one of two forms: `(recovered <path>: N lines, complete from the tool stream; NOT verified against disk)` followed by an `also in this window:` line counting the commands it could not read, when the window holds any, and `(recovered <path>: N lines, complete; no bash mutation of this file and no opaque mutating-class command detected in the window)` when it holds none (measured: `csift recover @<uuid> --no-subagents --file PATH` on three files of a live session, and on a synthetic session with no shell commands).

## recover JSON

Every mode emits header, rows and a `{kind:"summary", file, mode, sessions, skipped_lines}` line plus the crossing keys. `coverage`: `file`, `covered_ranges`, `boundaries`, `hard_boundaries`, `soft_boundaries`, `events` (per-op counts incl. `read_full`, `read_windowed`, `edit`, `write`, `bash`, `bash_read_anchor`, `bash_write_anchor`, `history_snapshot`, `stale_hint`, `stale_recovered`, `blanked_read`), `abandoned_events`, `fragments`, `recoverable_lines`, `seen_total_lines`, `opaque_commands`, `powershell_commands`, `suggested_search` (measured: `csift recover @<uuid> --file PATH --coverage --format json`). `snapshot` (`--at`, `--salvage`): `lines`, `gaps`, `seen_total_lines`, `boundaries`, `abandoned_events` and the same counts. `segment` (`--patches`): `segment_index`, `line`, `line_start`/`line_end`, `turn_start`/`turn_end`, instants, `pre_state_known`, `anchor_source`, `unified_diff`. `restore`: `file`, `complete`, `lines`, `boundaries`, `bash_events`, `opaque_commands`, `powershell_commands`, `suggested_search`, and `content` (or `path` and `wrote` under `--out`); a failed restore still emits `{kind:"restore", complete:false, reason}` and the summary before its non-zero exit. `backup` (`--list-backups`): `session_id`, `version`, `path`, `bytes`, `backup_utc`/`backup_local`, under a header carrying `mode`, `file`, `hash`, `store`, `store_present`. A boundary object: `line` (the replay coordinate `--at @line:` takes), `source_session_id` and `source_line` (the real transcript address to give `csift show`), `turn_index`, `survival`, `abandoned_root_line`, instants, `cause`, `confidence`, `detail`.

## plan

`csift plan TARGET --no-subagents` names the plan file bound to a session (without `--no-subagents` every subagent's binding is listed too: 706 lines for a session with 117 subagents, measured: `csift plan @<uuid>`); with no target it answers for the calling session and its subagents, from `$CLAUDE_CODE_SESSION_ID`, which inside a subagent names the parent session (measured: `csift plan --format json` from a subagent returned 1,436 `plan` rows, the parent session's and its lanes'). The binding follows Claude Code's own two rules in order: the `plan_mode` attachment's path when one exists, else the first record carrying a `slug`, binding `<plans dir>/<slug>.md` (in a subagent transcript `<slug>-agent-<agent id>.md`); no path is ever guessed (docs: `csift plan --help`). The text row prints the path with `[exists]` or `[missing]`; `[missing]` is ordinary, since the file appears only when content is first written. What is on disk now: read the path. What the session last had, or a deleted plan: `csift recover TARGET --file @plan`. `--reverse PLAN_FILE` finds the sessions bound to a plan file.

Whether a plan was approved is the result of its `ExitPlanMode` call: `csift search '' TARGET --no-subagents -t agent.tool.result --format json | jq -c 'select(.kind=="exchange") | .hits[] | select(.tool_name=="ExitPlanMode") | {line, ts_utc, denial_kind}'` lists each one, `denial_kind` null for an approval (its text opens `User has approved your plan`) and `user-rejected` for a rejection, which with a typed reason is also that session's `user.rejection` hit, ending `[plan: <path>]` where the plan resolves. The edits made after an approval are `csift files TARGET --no-subagents --by timeline --since <its ts_utc>` (measured on one session: one rejection and one approval, and 232 of its 244 mutations after the approval's instant).

JSON `plan` rows: trio, `plan_file` (not `path`), `plan_exists`, `line`, `slug`, `binding_source` (`plan_mode` or `slug-only`), `minted_at_compaction` (true when the slug's first carrier is a compaction boundary, which mints a slug even without Plan Mode); the header is `{command}` only; summary `{plans}` (measured: `csift plan @<uuid> --no-subagents --format json`).

`--audit` reports every structured edit the scope made to a file SOME session binds as its plan, warning when the editing session does not bind it itself (after a compaction only a session's own bound plan is re-injected in full, so content parked in another session's plan file does not come back). It joins against every project's bindings, so it is slow (measured: `csift plan @<uuid> --no-subagents --audit` took 16 s, a cost set by the size of the whole projects root rather than by the target). Each binding is qualified by the slug's change points (`slug  L<n>  none -> <value>` is the mint; two change points means the binding moved), `[exists]`/`[missing]`, a `plan-unbound-text` warning for re-injected plan text with no slug bound anywhere, and `slug_vs_plan_file` (`before`, `after`, `same`, `unknown` with a reason). JSON: `binding` rows (trio, `plan_file`, `line`, `slug`, `plan_exists`, `slug_changes[{line, from, to}]` with a null `from` for the mint, `first_slug_line`, `first_slug_utc`/`_local`, `slug_vs_plan_file`, `slug_vs_plan_file_reason`; no `binding_source`), `plan-unbound-text` rows `{session_id, plan_file_reference_lines}`, `plan-edit` rows `{owner_session_id, path, mutations, bound_by_owner, binder_session_id, binder_line}`, and a summary `{bindings, plan_files_touched, warnings, unbound_plan_text, skipped_lines}`.
