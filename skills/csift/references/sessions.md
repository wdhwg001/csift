# Sessions: list (which session, where it came from) and stats (tokens, tool calls, turns)

Read this before identifying a session, listing sessions, reading a session's lineage (clone, `/clear`, background handoff), totalling tokens, tool calls or turns, and whenever a session id may sit under two project directories or a transcript may have been deleted.

## Contents

- list
- Lineage: four links between transcripts
- One session id under two project directories
- stats
- Retention: transcripts Claude Code deletes

## list

`csift list TARGET --no-subagents` prints one row per session from a read of the head and tail of each file, so it stays fast on large transcripts; only `--lineage` adds a whole-file pass (Lineage, below). Always pass `--no-subagents` when you want sessions: the default includes subagent transcripts, and on a fan-out host the most recent rows are mostly subagents (measured: `csift list --max-count 8 --format json` returned 6 subagent rows of 8). With no target it lists every project and stops at the 50 most recently active rows, reporting the rest (measured: `csift list --format json` gave 50 rows and a `dropped_by_cap` count of the rest); a targeted run is uncapped, and `--max-count N` overrides either. The cap keeps the most recent sessions, but the rows print by project directory, then session id, never by time (measured: `csift list <project> --no-subagents --max-count 6 --format json` printed ids in ascending order with last-activity dates out of order, and an unscoped `csift list --no-subagents --max-count 5 --format json` sorted its rows by directory first), so sort by the `last_*` instants yourself when recency matters. The header's `sessions_in_scope` counts the scope before the cap. `--since`/`--until` keep a session whose first-to-last activity span overlaps the window.

A text row reads `SESSION  <uuid>` (two spaces, measured: `od -c`; a subagent row `SUBAGENT  <agent-id>  ·  parent SESSION <uuid>`), then `cwd` (the FIRST cwd seen, since the record cwd follows the shell's cwd), branch and Claude Code version (the LAST seen, with a `first->last` arrow when they changed), `first ◂`, `last ◂` and `last ▸` excerpts, cut near 200 characters with a `(+N chars)` marker (measured: the longest `first_user.excerpt` over 40 rows of `csift list --no-subagents --max-count 40 --format json` was 215 characters with its marker), with their instants, and any lineage rows below. `last ◂` can be an automation pulse rendered as its label.

JSON `session` row: the id trio; `path`; `cwd`; `git_branch`, `git_branch_first`, `git_branch_last`; `version`, `version_first`, `version_last`; `first_user`, `last_user`, `last_agent` (each `{excerpt, ts_utc, ts_local}` or null); `skipped_lines` (malformed lines among the lines READ, not the whole file; `stats` counts the whole file); `sidecar_present`, `pending_elicitations`, `with_elicitation_sidecar` (references/live.md); the lineage keys below; `also_at`, `also_at_count`, `duplicate_relation`. Summary `{sessions, dropped_by_cap, skipped_lines}` (measured: `csift list @<uuid> --no-subagents --format json`).

`sidecar_present` is true when the session has an elicitation sidecar file, and `pending_elicitations` lists its markers no result has closed. A listed marker is a question waiting now only while the transcript has not moved past it and the session is alive; one the transcript has moved past, or one in a session with no live registry row, is a marker whose result never arrived and waits on nothing (references/live.md, Pending questions). False means no elicitation was ever recorded for the session, which is also what a session reads when no marker hook is installed, so false alone does not prove nothing was asked.

## Lineage: four links between transcripts

Each is independent and one row can carry all four. Two are inferred and say so; two are stated by Claude Code.

| link | text row | JSON | how it is known |
|---|---|---|---|
| clone | `clone    forked from SESSION <uuid> at compaction boundary <uuid>` | `is_clone`, `clone_of`, `clone_boundary_uuid` | inferred: the transcript's first timestamped record is a compaction boundary, which is what a background job's copy of another session looks like (record uuids kept, timestamps older than the file). A clone repeats its origin's records, so a spanning count over both counts them twice until one is scoped away |
| `/clear` | `cleared  from <id8> (an inference: the checkpoint the clear wrote closes N ms after this file opens)` | `minted_by:"clear"`, `cleared_from`, `cleared_from_distance_ms`, `cleared_from_candidates` | inferred: the first non-isMeta user record is the `/clear` command itself, and the predecessor is the sibling in the same project directory whose `cost-state` checkpoint (`startTime + totalDuration`) closes within 2000 ms of it (docs: `csift list --help`); a tie between two files joins neither and lists both. A clear writes no lineage on disk and drops the plan binding |
| background handoff | `handoff  continued in <id8> (a background handoff: Claude Code names the child itself, so this one is no inference)` | `continued_in` | stated: Claude Code appends a `continued-in` line to the parent naming the child. An in-place `/fork` writes none, so absence proves nothing, and the line is written even when the child failed to start. A later resume of the parent can push the line out of the tail window, where the field reads null |
| minted elsewhere | `minted   a record here names <id8> as the session it was minted in`, then a note in parentheses | `minted_elsewhere`, `minted_elsewhere_count` | stated: a record whose snake-case `session_id` differs from its own `sessionId` was hydrated from another session through the Remote Control bridge; a set, since one file can hold runs from several |

A background lane's records carry `sessionKind:"bg"` and a foreground lane's carry none, so `session_kind` is an array: `[]` for an ordinary session, `["bg"]` for a background one. `--lineage` makes one whole-file key pass that adds the background span (`session_kind_first_line`, `session_kind_last_line`, text `lane     bg on L<a>..L<b>`), finds a handoff line the tail window missed, and answers `minted_elsewhere`; without it those read null or empty and `lineage_scanned` is false (measured: `csift list @<uuid> --no-subagents --lineage --format json`).

## One session id under two project directories

A renamed project whose directory was copied leaves one session id under two directories, and Claude Code's own directory-name override and relocation fallback reach the same shape. csift decides by the bytes (docs: `csift --help`):

| relation | outcome |
|---|---|
| `identical`, or `prefix` (one copy a strict byte prefix of the other) | merged onto the longest copy; `list` gives one row with `also_at` naming the others |
| `divergent` (a byte differs before the shorter copy ends) | nothing merged; each copy keeps its own row, though `sessions_in_scope` counts the session once |
| `unknown` (a copy csift could not read) | nothing merged; a command that reads every file in scope then fails on that copy, after naming it on stderr |

Every merge is named on stderr (`csift: note: session <id8> is on disk under 2 project directories (byte-identical copies); keeping <path> ... and dropping 1 copy ...`) and counted in the JSON header (`duplicate_transcripts`, `duplicate_records_dropped`, `divergent_transcripts`, `unreadable_transcripts`). One agent id can also sit at both sidecar locations of one session, the built-in and a workflow run's, and takes the same rule. The text output of `search`, `stats`, `files`, `verbatim`, `agents` and `image` over such a session opens with a stdout line `copies session <id8> is on disk under 2 project directories ...` before its head, and a `list` row carries a `copies` line of its own (measured: each on a synthetic home holding one session under two directories with one byte changed, and `csift stats @<uuid> --no-subagents` on a live session held as two byte-identical copies). `show` refuses an address that resolves to two files and names both paths; target the `*.jsonl` path of the copy you mean, which on `show` reads that file and no other, and on a spanning command reads it with its subagents unless `--no-subagents` is given (SKILL.md, Targets). A Claude home reached through a symlink beside its real path is reported as two identical copies of every session in it; point `--claude-home` at the real path instead.

## stats

A token or spend total for a session spans its subagents: `csift stats @<uuid> --format json | tail -1 | jq .tokens` totals the session and every subagent transcript, while `--no-subagents` keeps the top-level thread alone, which is right only when that thread is the question (measured on one session: 62,321,518 `claude-opus-5-5` output tokens over 813 transcripts spanning, 3,828,219 with `--no-subagents`). `csift stats TARGET --no-subagents` prints one block per transcript: `lines`; `records N user + M assistant`, every `type:"user"` and `type:"assistant"` line, tool results included, so N is not the person's messages (measured on one session: 835 user records against 33 `user.message`, which `csift search '' @<uuid> --no-subagents -t user.message --count-by label` counts); `turns`; compactions; `types` (every physical line counted by its top-level `type`, the answer to what else fills a jsonl); `chain` (abandoned turns, the rewound subset, replay copy lines, and boundaries crossed, printed when there is something to say); `span` (first and last instant, and the duration); `tokens` per model as input, output, cache-read and cache-write, counted once per API message, because Claude Code repeats the same usage object on every record of one response (docs: `csift stats --help`; measured on one session: 8,912,452 output tokens summed over every `--raw` assistant record against `stats`' 3,000,947, which one record per `message.id` also gives); narration blocks per model; `tools` as calls per tool name (measured: `csift stats @<uuid> --no-subagents`). `tools` counts calls, where `search --count-by tool` counts records, a call and its result being two (references/search.md, Census axes). Without `--no-subagents` it prints a block for every subagent too, then a `TOTAL` block (measured: `csift stats @<uuid>` printed 842 lines against 11 with `--no-subagents` on a session with 117 subagents); for the scope's totals alone read the JSON summary: `csift stats TARGET --format json | tail -1 | jq .tokens`, which totals every session in scope unless `--max-count` narrows it (below).

`--turn` and `--since`/`--until` window the counts, except `lines`, `types` and the three chain totals, which describe the whole file: `csift stats @main --no-subagents --turn -5..` is the burn of the last five turns of the calling top-level session, which from a subagent is the parent's, not the subagent's own (SKILL.md, Targets, `@main`). `turns` counts the numbered turns, pre-cut ones included, the numbering `search` and `show` print; `search --count-by turn` returns one more row, `t? (abandoned)`, when the file holds abandoned records (measured: 57 turns against 58 census rows on one session). `stats` is the whole-file authority on malformed lines in the transcript (`skipped_lines`), which `list` counts only among the lines it reads. `search`, `verbatim` and `list` also count the lines of the session's elicitation sidecar that the current marker format cannot read, which `stats` never opens, so their `skipped_lines` can exceed `stats`' (measured on one session with such a sidecar: 4 against 0).

JSON `session` row: the id trio, `lines`, `line_types`, `user_records`, `assistant_records`, `turns`, `abandoned_turns`, `rewound_turns`, `replay_copies`, `compactions`, `first_utc`/`first_local`, `last_utc`/`last_local`, `tokens{<model>:{input, output, cache_read, cache_creation}}`, `narration_blocks`, `unknown_thinking_tags`, `tools{<name>:<calls>}`, `skipped_lines`, and the crossing keys at a non-zero `--cross-compactions`. Summary: `sessions`, `dropped_by_cap`, and scope totals of `turns`, `abandoned_turns`, `rewound_turns`, `replay_copies`, `line_types`, `tokens`, `narration_blocks`, `unknown_thinking_tags`, `tools` and `skipped_lines`, plus the six crossing keys; it carries no `lines`, record counts, `compactions` or span instants (measured: `csift stats @<uuid> --format json`). `--max-count N` keeps the N most recently active sessions and reports the rest, and the summary's totals then cover only the kept sessions; the header counts the scope before the cap (measured: `csift stats <project> --no-subagents --format json` summed 23 sessions and 1,776 turns, the same with `--max-count 1` 1 session and 1,510 turns with `dropped_by_cap` 22, header `sessions_in_scope` 23).

## Retention: transcripts Claude Code deletes

Claude Code deletes a transcript once its last write is older than `cleanupPeriodDays`, 30 days by default (docs: `csift --help`, RETENTION), and its sidecar tree goes with it: subagent transcripts, tool-result files and csift's own sidecars (docs: SPEC.md section 6, the retention note, https://github.com/wdhwg001/csift/blob/v0.13.0/SPEC.md). `jq '.cleanupPeriodDays // 30' ~/.claude/settings.json` prints the user-scope value; a project or managed settings file can override it (UNTESTED). csift reads only what survives: an old session that `list` cannot find may simply be gone.
