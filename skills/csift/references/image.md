# image: list and extract images a session carries

Read this before listing, citing or extracting images from a session (pasted images, screenshots in tool results, PDF pages a Read returned), and before using an image handle printed by `search` or `verbatim`.

## Listing

`csift image TARGET` lists, without writing anything, every image stored inline in the scope's records, subagent transcripts included unless `--no-subagents` is given, deduplicated by content: one row per image, `#1    L403i1  image/png ~54 KB  <local instant>  [pre-cut]` (measured: `csift image @<uuid>`). Rows sort by paste number, then line, not by time, so the last row is not the newest image (measured: `csift image @<uuid> --no-subagents --format json` on one session: 66 rows, 23 of them earlier than the row before, the last dated a month before the newest); the newest is `csift image @<uuid> --no-subagents --format json | jq -s 'map(select(.kind=="image")) | sort_by(.ts_utc) | last | {id, line, ts_local}'`. Three carriers are read: an image block on a user or assistant record, an image inside a tool result (a screenshot), and the image blocks of a `queued_command` attachment's prompt, which is the only copy of a picture pasted into a prompt that was edited or recalled before it was sent. An image stored as a URL has no bytes on disk and is reported, never invented. A row does not say which of the three carriers held it: JSON `source_kind` reads `base64` on every inline image (measured: 66 of 66 rows on that session), so fetch the record at its `L<line>` with `csift show` to see the carrier. The listing therefore mixes what the person pasted with screenshots and PDF pages; for the person's pastes alone, list the person's own messages that carry images, and the skill bodies, because images pasted with a slash command that loads a skill ride the skill's `harness.context.skill` record while the command's own `user.message` line, one line above, carries their `[Image #N]` markers only: `csift search '' @<uuid> --no-subagents -t user.message -t harness.context.skill --format json | jq -r 'select(.kind=="exchange") | .hits[] | select((.image_ids|length)>0) | "L\(.line) \(.image_ids|join(" "))"'`, and address each image as `L<line>i<n>`, n counting that record's images from 1 (measured on that session with `-t user.message` alone: 66 handles on 42 lines, the same 66 images on the same 42 lines `csift image @<uuid> --no-subagents` listed; on another, the skill record at L11 carried `#2 #3 #4`, the images its `/<command> [Image #2] [Image #3] [Image #4] ...` line at L10 named).

Two addresses, both per transcript:

| address | is |
|---|---|
| `#N` (pass `--id N`, without the `#`) | the paste number Claude Code showed as `[Image #N]`, joined to each image block through the record's `imagePasteIds` in block order, because the `[Image #N]` markers in the text keep the order the person typed them. It is not a dense index: numbers can start above 1 and have holes, and one number can name several images across prompts, in which case `--id` exits non-zero listing the occurrences (docs: `csift image --help`); narrow with `--since`, `--until`, `--turn` or `--uuid <record uuid prefix>` |
| `L<line>i<n>` | the record's jsonl line and the image's position in it; always unique |

`--id` and `--turn` each need exactly one image-carrying transcript in scope: a spanning scope in which only one transcript carries images is accepted, and one in which several do exits 1 with ``csift: error: --id is per-transcript (line numbers and `#N` are), but the scope resolves to <N> transcripts — pin it with `@<uuid> --no-subagents` `` (``--turn is per-transcript (turn indices are) ...`` for `--turn`) (measured: `csift image @<uuid> --id L<n>i<k>` and `--turn -1` over a scope of 1,436 transcripts, one carrying images, exited 0; `csift image @<uuid> --id 1` over three image-carrying transcripts, and `--turn -1` over 121, exited 1). An unknown handle exits 1 naming the handles that exist (`csift: error: --id matched no image: #<N> — present here: #<n> ...`), and a scope with no images at all exits 1 with `... — the scope carries no images at all.` `search` and `verbatim` print the same handles inline (`[1 image: #265]`, `[2 images: #1, #2]`), so a line that carries an image says so and names it.

An image on a record the conversation no longer reaches is still listed and extractable, marked `[abandoned]`, and one above a compaction floor `[pre-cut]` (references/survival.md); `--turn` windows on live turns and leaves abandoned records out.

PDF pages: a `Read` of a PDF with a `pages` parameter returns one image per page, so the pages list like images, each with ` p<N>` beside its media type and the document's basename once per record. csift computes the page from the result's `toolUseResult.firstPage` and the element's position, and prints `page: null` wherever that is not certain (a screenshot, a result from before the field existed, a record carrying two tool results). A whole-PDF `Read` without `pages` returns a `document` block, which is not listed; `csift show TARGET --line N --raw` reaches it (docs: `csift image --help`).

JSON: `image` rows `{handle, seq, id, line, img_index, session_id, is_subagent, parent_session_id, source_kind, media_type, b64_len, est_bytes, url, page, pdf_path, record_uuid, survival, ts_utc, ts_local}` (`img_index` counts images across the whole record, not pages); `extract` rows under `--out` `{handle, seq, id, session_id, is_subagent, parent_session_id, path, bytes, media_type, source_media_type, converted, notes}`; a summary `{images, transcripts, skipped_lines}` plus the crossing keys; the header carries `command`, `sessions_in_scope`, `top_level_sessions`, `subagent_sessions` and the four duplicate keys (measured: `csift image @<uuid> --format json`).

## Extracting

| action | irreversible: the command, its preview, the rule |
|---|---|
| write images to files | irreversible: `csift image @<uuid> --no-subagents --id ID --out PATH` writes the selected images and replaces a file of the same name. A PATH without an image extension is a directory: each image is written in its source format as `<session>[-img<N>]-L<line>i<n>.<ext>`. A PATH ending `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp` receives one image, converted (JPEG and WebP at quality 90, GIF with a dithered palette; an animated GIF keeps its first frame and warns; docs: `csift image --help`). Preview with `csift image @<uuid> --no-subagents --id ID` (the same selection, listed) and `ls -l PATH`; run only after the user's reply to that preview says go |

After extracting, read the file with the Read tool to see the image.
